CODING BUDDY · TAKE-HOME REFERENCE

A clue, then a little more.

One desktop VS Code extension connects a saved code file and its run result to a chosen AI provider. The AI writes teaching guidance; local rules decide how specific that guidance may become. Suggested edits stay under the learner’s control.

Implementation snapshot: 7c4f2e2

Follow one code run

First clue → three changed-code retries → inline arrow → three more retries → a proposed diff with an explanation. Identical reruns with unchanged context do not advance the count or make another request.

A practice to reuse

Turn a vague requirement into a result you can check. “After many tries” became the three-plus-three rule in the PRD, then LearningSession in the code, then tests that verify exactly when arrows and fixes become available.

On another AI-assisted project, define one observable outcome before asking for code, and require evidence for it. Here, session tests check the rule, while the VS Code host test checks real terminal and editor behavior. Neither substitutes for live model evaluation.

What is remembered, and what is sent?

VS Code remembers provider/model preferences and the confetti setting. Keys use its secret storage. Current hints, code snapshots, and counts remain in memory until restart. Only the selected provider receives connected code, relevant output, and clarification; provider data policies still apply.
