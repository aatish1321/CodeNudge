# CodeNudge: planning and evidence

This directory contains the project artifacts generated while building with the [Devpost Learn Skill Pack](https://github.com/challengepost/learn-ai-basics) for [Build With AI: Basics](https://learn-ai-basics.devpost.com/). The product was originally planned as **Coding Buddy** and is now **CodeNudge**. Original decisions and later revisions remain visible in the plans and Git history.

## Required planning documents

The [challenge rules](https://learn-ai-basics.devpost.com/rules) require the skill-generated scope, PRD and spec in the public repository. All three are substantive, committed files with approved status:

| File | Read it for |
| --- | --- |
| [scope.md](scope.md) | Audience, unique kernel, scope boundary and later scope revisions. |
| [prd.md](prd.md) | Core journey, clue/inline/fix rules, user control and acceptance criteria. |
| [spec.md](spec.md) | VS Code architecture, provider connections, context handling, storage and checks. |

These are the original project plans, not copies of the installed skill templates.

## Implementation and verification

- [checklist.md](checklist.md): build slices, implementation checkpoints, changes and review status. Unchecked items are not silently counted as completed.
- [app-map.html](app-map.html): source-linked reference to the learning workflow. GitHub shows the HTML source; download and open it locally to use the map.
- [verification.md](verification.md): recorded source/native checks, live Groq probes and explicit limitations.
- [groq-stage-checks.json](groq-stage-checks.json): the recorded live Debug-stage probe results. They do not establish every provider or a complete live Project-mode journey.

For the current extension, start with the [repository README](../README.md), [usage guide](../docs/usage.md) or [source](../src). The [Marketplace release record](../docs/marketplace-release.md) separates release verification from earlier development snapshots.
